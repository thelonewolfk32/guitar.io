# Guitar.io V1.5.0 local device sync

V1.5 retains the existing LAN protocol/schema, including the metadata repair and recent-activity sync described below. Windows/Mac are released; native iPhone compilation and device verification are pending. See [IOS_HANDOFF.md](IOS_HANDOFF.md) for the current Mac/iPhone setup. GitHub source/app updates and private-library LAN sync are separate connections.

Enable Device sync from the header. Choose Add device on the other device and enter the six-digit PC/Mac code. Compare the verification digits and confirm on both screens. Paired apps reconnect through Bonjour on the same Wi-Fi/Ethernet LAN, with saved private IPv4 addresses as fallback. Devices must be awake with Guitar.io open. iOS syncs foregrounded and catches up on resume. Allow Local Network access on Apple devices and local firewall connections on desktops. Client-isolated Wi-Fi can block peers.

Initial pairing transfers catalogue/edit metadata once. Revision-indexed queries then return only fields/map keys changed after each peer's checkpoint. Routine checks exchange a small head revision. Separate pull/push checkpoints prevent an unrelated Mac change being skipped after a newer PC change. No routine catalogue scan, GP parsing, full-library fetch or full-library save on exit.

GP/audio begin as missing-file descriptors. Opening downloads 512 KiB encrypted chunks from an awake paired device and caches them for offline use. Artwork fetches as cards request it. Immutable IDs/hashes prevent refetching unchanged bytes. Two simultaneous downloads, interrupted-download resume, a 64 MiB/seven-day temporary cache and old journal compaction limit resource use. Files over 64 MiB retain a resumable prefix and finish in memory chunks. Scores are limited to 30 MiB, attachments to 250 MiB. iOS LAN requests never use cellular.

With Auto sync enabled, clients check every 30 seconds while open, wake after a debounced save/reconnect/foreground, and retry failed peers. Catch-up is paginated and bounded. Incoming edits wait until the library so an editor/player is not overwritten. Device sync displays errors and transferred bytes. Disable Local sync to close desktop discovery/listener and stop outgoing requests.

IndexedDB guitar-io-v1 upgrades once to schema 4, retaining device identity and existing origins/files. syncEntities stores cumulative fields/map keys/tombstones indexed by latest revision. Each field clock is logical UTC timestamp + stable device ID + origin sequence; the local clock observes received timestamps. Independent fields merge, same-field conflicts deterministically pick the newest. Invalid or overlapping ranges abort the page without advancing its checkpoint. Apply/checkpoint is atomic; repeated delivery generates no echo revision. Accepted remote stamps forward unchanged to another peer.

The diagnostic journal compacts after 2,000 revisions while current state/tombstones remain indefinitely for offline peers. syncTransfers/syncTransferChunks cache interrupted bytes. Thumbnails stay local derived data. Pairing keys/checkpoints live in device settings and are excluded from format-2 song backups.

AES-256-GCM messages use fresh nonces, protocol AAD and request/response identity binding over private IPv4 HTTP. The host rejects public peers, redirected targets, replayed/expired requests and oversized bodies. Keep automatic system date/time enabled (requests expire after two minutes). Bonjour advertises ID/name and the six-digit discovery code, never a key. The six digits identify a host and are not an encryption password. A one-time P-256 ECDH exchange with committed public keys/nonces and HKDF-SHA256 derives an independent 256-bit session key; matching verification digits on both devices and explicit host approval authenticate the exchange before sharing the persistent AES key. Requests expire after two minutes and init attempts are capped at five per minute. The legacy long-code path remains for existing V1.4 clients. Reset a host code to revoke old incoming keys; clients must re-pair. Removing a peer stops outgoing connections and records a local rejection for that device identity. Re-pairing with host approval clears the rejection.

No cloud account or router forwarding is needed. iOS is a bidirectional client of desktops; direct phone-to-phone hosting and IPv6-only LANs are not implemented. Transport-independent field clocks/deltas/content references provide the basis for a later cloud adapter. See IOS_HANDOFF.md for native build/testing and platform limitations.

Auto sync off disables automatic outgoing checks, including save/foreground timers. Sync now still performs a manual check; paired peers may still send incoming updates while Local sync is ON. OFF closes the listener/discovery and stops connections. Pairing desktop peers is reciprocal; iOS clients are listed on hosts but are not polled as servers. No library/storage migration or full-library rewrite is introduced in V1.4.1.
# V1.4.3 metadata repair and diagnostics

Install V1.4.3 or later on both paired devices, then use Sync now. Existing checkpoints and cached files remain valid. Unknown records receive their complete base metadata before a partial edit is applied. This repairs the earlier Incomplete song metadata error caused by projecting an edited, previously unseen entity past a global checkpoint. Known records retain small field/map deltas. Base repair does not download GP/audio bytes or scan every original file.

Album names, artwork references, lastOpenedAt, lastPlayedAt and lastPlayedBar travel as song metadata. Artwork can be unavailable without preventing the album name, tab or playback history from arriving. Image requests retry after metadata updates; matched album names also survive failed online artwork downloads.

Device sync → Show diagnostics (OFF by default) lists the current stage, named song transfers, revisions, endpoint errors and failed file IDs. Export report saves a local JSON file with the catalogue metadata, checkpoints, LAN addresses and the latest 120 log events. No pairing secrets, codes, encrypted envelopes, GP/audio bytes or annotations are exported. Logs remain local and bounded; they are not sent to GitHub.

A no-change sync still exchanges a small encrypted head-revision request/response. The session counter estimates the encoded envelope traffic, including headers inside the JSON protocol, rather than raw GP sizes. Files are downloaded in chunks when opened or requested by visible artwork/preview consumers, and cached locally. A failed metadata page does not advance its checkpoint. Errors name the failing entity so the next check can retry it safely.

Ethernet and Wi-Fi can share the same LAN. Routed addresses take priority over inactive 169.254 adapters, and the last working endpoint is reused first. Repeated validation errors are not retried through every network address. If pairing fails, the log separates a discovery failure from an endpoint or application error. No firewall settings are automatically modified.
